# F-CCP 证明、实现与数值审计

## 1. 核查范围与状态

新结论已形成书面证明，并完成本文件列出的内部审查。没有独立同行审稿、隔离证明代理或形式化系统验证；诊断不构成普遍概率命题的证明。

本轮读取了用户的证明 protocol 和 adversarial audit，创新性评估读取了 SKILL、rubric 与 repeated-assessment。未虚构五个独立评分，评价实际为当前上下文单次。

## 2. 证明依赖

1. 标签可靠性复用旧 CCP 的 bounded beta-mixture 超鞅、潜在前缀覆盖及事前固定检查点。冷温度只用于动作评分。
2. 新双预算界调用旧 CCP 定理 D（任意动作的 MC 指数差 regret 界）和独立 temporal-geometry 的谱比较；新证明明确写出了这两个依赖。
3. 两个账本分别计入实际收益轮与实际认证轮；拒绝服务只有一次实际收益拉取，不生成未观测服务奖励。
4. 在预先固定有限 β_R、β_C 下，预算单调且最大虚拟指数动作始终可行。
5. 正服务率下的面积界只在共同覆盖事件上成立。β_C=∞、λ=1 可得到最坏面积阶；有限 β_C 的拒绝项不删。
6. 有限臂最终完成需要 β_C>0 与忙轮 p_min>0；λ=0、任意趋零 λ_t 不自动符合。
7. 完整前沿、默认精确最优、每个环境优于独立运行的所有基线均未证明。两臂首轮反例只否定严格零余项全环境同时支配。
8. 原稿最坏面积下界需 ε≤1/8、η≤ε/32、δ≤1/16。多数实践测试不在这个狭窄匹配范围内；不能用那些实验宣布验证匹配渐近率。

## 3. 实际实现诊断

`results/implementation-audit.json` 记录全部检查通过：

- 50,000 个实际时刻：交互 API 的兼容模式与独立状态/随机数的 UCB1、Growing-MOSS、MC-MOSS、Thompson、KL-UCB 基线逐动作、逐计数一致。
- 800 个随机状态×核测试：在未到达数组区域加入不同哨兵数据，不改变动作或记账，证明实现未读取未来存储槽的诊断证据。
- 126 个置信区间反演诊断：零样本、端点、极低均值、不同样本数与错误预算；检查外向求根。
- 10,000 组可变服务率公式检查。
- 4,000 轮含中途偏好改变的运行：历史、区间、相位和预算从不清零，两个预算均受控。
- 参数与调用顺序错误处理；单臂报告；两环境无劣性反例代数核对。

交互 API 使用自己拥有的 NumPy Generator，批量实验使用 Numba RNG。两者是同一规则分布，不保证跨后端相同 seed 的动作逐位一致；没有声称这种不存在的位级等价。

## 4. 实验冻结与实际数量

开发三轮分别为 2,640、5,616、5,760 条有效轨迹，共 14,016 条。开发环境/种子与主测试不同；任务类型有交叠。最后一轮采用预设等权场景平均 regret 选择纯收益候选。

主测试冻结 12 个新实例、24 个配置、96 个配对重复：27,648 条轨迹。每个方法在同一重复看到同一条臂的相同潜在奖励前缀；同一批臂的均值标签共同随机置换。真正动作选择函数只获得已到达前缀、历史统计和随机化，不知道 T、均值或未来到达。

主测试冻结后的 F-CCP 与纯收益基线代码哈希未改变。全部轨迹满足真实观测总次数=物理终点。检查包含所有失败和回退路径；没有挑选“覆盖正确”的子样本再计算平均 regret。

## 5. 审计发现与处理，不能隐去

### 5.1 ALL 适配的经验采样成本输入

初始 `service_plan` 的 ALL 分支返回了服务臂和固定0作为第二返回值。对于固定服务比例或 λ=1，第二返回值不影响动作；但对于新的成本敏感自适应控制，它使 ALL 的 `p_t` 不按拟选臂的经验收益差缩减。这不是一个可以解释为“只差调度”的公平消融。

修正方式：F-CCP 不变，仅把 ALL 分支的第二返回值改成由同一置信矩形内规划中心计算的 max(mid)-mid[action]。冻结 `matched-all-freeze.json` 后，在相同12场景×96重复上补跑1,152条，命名 `ALL-auto-costmatched`。不调整任何其他参数、不据此重新选择 F-CCP。初始 `ALL-auto-0.6` 的数据保留，但不作为主分配优势证据。ALL-area、ALL-original-budget 的原结果不受此返回值影响。

### 5.2 相位累积的浮点边界

精确算术有 attempts=floor(Σp_t)。浮点实现对固定0.6等值在整数边界可能晚一个服务槽；主测试1,035条记录出现这一现象。全部数据的 Σp−attempts 在 [0,1+3×10^−9] 内。

保留原始轨迹与动作；没有为修正一个计数边界而事后改动主要排名。`theory.md` 说明数学结论用精确算术，数值实现不构成严格形式证书。面积工作量诊断采用允许末端一个槽差的容差；不把全局累加舍入误差当成实质失败。

### 5.3 编译和汇总过程错误

首轮开发最初因 Numba 不接受 `float(bool)` 编译失败，没有有效轨迹。修正后重新冻结并完成开发；失败日志保留。汇总脚本的 JSON NumPy 整型与相位诊断表达也经过修正，但没有修改任何已冻结算法或原始结果。

### 5.4 真正的报告失败

不能再沿用“全部零错误”的前两轮描述。本轮 ceiling 场景第75个重复的同一潜在流，在若干配置下出现错误确定标签。默认 F-auto-0.6 有1/1,152条轨迹出现误标，F-R 与 F-area 均为0/1,152；置信覆盖失败和空交集也存在，均计入结果。方法间共享奖励，事件不独立，不把重复配置数量当成独立可靠性试验数量。

## 6. 比较标准与解释

原任务中“期望regret不差于所有基线”的全环境版本不可能；有限样本也不能从未显著发现差异推导非劣性。

测试前另外规定了一个宽松参考门槛 E R_F≤1.05 E R_B+2；这不是用户的零容忍条件。60个场景×基线配对比较以 Bonferroni 单侧 t 区间报告：59个点估计更低、52个零差上端点低于0、54个宽松门槛上端点低于0。没有把54/60写成全面通过。t近似的区间是 Monte Carlo 误差诊断，不是全模型或全部时刻的频率保证。

F-R 的平均收益改进不能解释成尾部也更好。在 burst、ceiling、larger_pool 等场景，其95%经验regret分位数高于标准TS；完整分位数与最大值已报告。

## 7. 当前最小未决理论接口

没有得到相对每条独立运行基线的低开销自适应选择器，没有把可观测预算直接转成给定目标面积的完整最优分配。基于经验待办成本的控制率是有保底的启发式，未证明最优。新证据足以支持参数化、可用性与一些实际比较，不支持给本轮调参工作附上全前沿最优性主张。
